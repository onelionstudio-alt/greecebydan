## Что исправлено при финальной проверке

Ранее выражение «аналитика выключена» означало лишь отсутствие сохранения событий: events.js всё равно выполнял fetch к /events, а генератор добавлял прежний Web Analytics beacon. Это не соответствовало выпуску без аналитики.

Теперь:

- В публичной сборке два явных disabled-флага. events.js возвращает no-op до регистрации обработчиков и до сети; браузер не отправляет события вообще.
- Web Analytics beacon из генератора удалён. Это не отключает необходимые инфраструктурные security logs или edge-статистику провайдера.
- У Worker `INTERACTIONS_ENABLED=false`; отсутствие явного true запрещает запись даже при случайно добавленных bindings. Dataset в конфигурации отсутствует.
- API-фото: `VIATOR_IMAGES_APPROVED=false` и клиентский запрет загрузки, даже если входящий DTO содержит image.
- Donation button остаётся ссылкой на прежний Buy Me a Coffee URL. Убран автоматически загружавшийся BMC-скрипт с непроверенным сторонним поведением. YouTube уже был внешней ссылкой.
- Активная Privacy больше не обещает работающую аналитику. Никакой consent banner не имитируется: optional functions выключены, а будущий opt-in требует отдельной реализации до сбора.

## Локальный workerd

Запущен Wrangler 4.151.0 в local mode с `wrangler.staging.toml`, на loopback, без секретов, production routes и Analytics Engine bindings. Не делался `wrangler deploy`, `secret put` или login. [Сохранённые ответы](local-workerd.json):

- /health → 200, ready=false;
- /destinations с допустимым Origin → 503 Setup incomplete;
- чужой Origin → 403;
- CORS OPTIONS → 204;
- /events → 503 Events disabled.

Это проверка среды выполнения и fail-closed поведения. Успешный поиск, живой limiter в облаке, аккаунтные квоты и реальная taxonomy не проверены.

## Изоляция staging

`travel-worker/wrangler.staging.toml` использует имя `greecebydan-travel-api-staging`, пустые routes и отдельный limiter namespace 1049. Production использует другое имя и namespace 1047. Оба флага выключены. Нельзя публиковать этот файл как production-конфигурацию.

Для продолжения в авторизованной Cloudflare-среде: проверить целевой account, развернуть ТОЛЬКО staging config, безопасно provision отдельный разрешённый Viator key через secret prompt, повторить health/destinations/boat/wine/empty/error и браузерный путь на staging. Секреты не передавать в чат или аргументах команд. Текущий Worker допускает браузерный Origin production; для независимого staging frontend потребуется отдельно согласованная allowlist origin без расширения production. Не заменять production API URL временной staging-ссылкой в выпускаемой сборке.
